# Code Sanitizer

業務コードを生成AIなどへ貼り付ける前に、会社名・製品名・顧客名などの文字列をローカルで匿名化するデスクトップツールです。Tkinterの画面で匿名化前後を確認し、結果を別ファイルへ保存したり、クリップボードへコピーしたりできます。

## ローカルでの動作

ファイルの読み込み、匿名化、漏れチェック、保存はすべてローカル環境で行います。外部APIや外部サーバーへの通信、クラウド保存、自動アップロードは行いません。

## 必要な環境

- Python 3.10以上
- Tkinter（多くのPython環境に同梱されています）
- `tkinterdnd2`（ファイルのドラッグ＆ドロップ用。インストール時に追加されます）

## インストール

リポジトリのルートで、必要に応じて仮想環境を作成し、インストールします。

```console
python -m venv .venv
```

Windows:

```console
.venv\Scripts\activate
python -m pip install -e ".[test]"
```

macOS / Linux:

```console
source .venv/bin/activate
python -m pip install -e ".[test]"
```

## 起動方法

インストール後:

```console
code-sanitizer
```

またはリポジトリのルートから:

```console
python -m code_sanitizer.app
```

## 基本的な使い方

1. 「ファイルを選択」から匿名化対象のテキストファイルを開きます。文字コードはUTF-8です。
   ファイルを匿名化モードのファイル欄へドラッグ＆ドロップして開くこともできます。
2. 「通常置換ルール」に検索文字列と置換文字列を入力して「追加」します。大文字小文字は区別されます。
3. 「行マスクルール」に文字列を入力して「追加」すると、その文字列を含む行全体が `[REDACTED]` に置換されます。
4. 「匿名化を実行」を押し、元コードと匿名化後コードおよび処理件数を確認します。ルールの追加・削除後もプレビューは更新されます。
5. 「結果を保存」で別ファイルへ保存するか、「結果をコピー」でクリップボードへコピーします。保存時の初期ファイル名は `元ファイル名_sanitized.拡張子` です。元ファイルへの上書きは拒否されます。

匿名化ルールは単純な文字列置換です。正規表現やコード構造の解析は行いません。

## 復元可能な匿名化と復元

従来の「匿名化を実行」はそのまま `[REDACTED]` を使い、復元情報を作成しません。「復元可能な匿名化を作成」を選ぶと、置換箇所ごとに `[REDACTED_0001]` のような一意のIDを割り当て、匿名化コードと復元情報JSONを別々に保存します。復元情報には元の文字列が含まれるため、保存場所を選び、ローカルのみで厳重に管理してください。暗号化は行わず、外部送信もしません。

「復元モード」では、匿名化時の元コード、AI修正後コード、対応する復元情報を選び、「復元を実行」します。IDの文字列だけを対応付けるため、IDの位置より前後に追加・削除された行や、ID以外のAI変更は維持されます。復元元の取り違えを避けるため、復元情報のSHA-256と元コードを照合します。

復元モードでは、「元コード」「AI修正後コード」「復元情報」の各入力欄へファイルを個別にドラッグ＆ドロップできます。従来どおり「選択」ボタンからファイルを指定する方法も使えます。

IDが消失・変更・複製された場合、未知または不正なIDがある場合、元コードまたは対応データが一致しない場合は推測せず警告し、問題のあるIDは自動復元しません。結果には復元数、未復元数、問題のあるID、人間の確認が必要な箇所を表示します。行マスクは行全体を一つのIDに置き換えるため、IDが単独の行として残る場合のみ行全体を復元します。同じ行にAI編集が加わった場合はIDを復元せず、未復元として人間の確認を求めます。行マスクの復元箇所は、復元後も必ず人間の確認が必要として報告します。

匿名化コードと復元情報は指定先に新規作成し、既存ファイルは上書きしません。復元結果の保存先に、元コード・AI修正後コード・復元情報を指定することもできません。復元情報と復元可能な匿名化ファイルは `.gitignore` の対象ですが、Git除外はローカルファイルの保護を保証しないため、復元情報を共有・送信・Gitへ追加しないでください。

## 設定の保存

通常置換ルール、行マスクルール、最後に使用したフォルダーはユーザー設定ファイルへ自動保存され、次回起動時に復元されます。設定はUTF-8のJSON形式で、Windowsでは `%LOCALAPPDATA%\\code-sanitizer\\settings.json`、macOSでは `~/Library/Application Support/code-sanitizer/settings.json`、Linuxでは `$XDG_CONFIG_HOME/code-sanitizer/settings.json`（未設定の場合は `~/.config/code-sanitizer/settings.json`）に保存されます。ソースファイルの内容と一時的に無視した候補は設定に保存しません。設定ファイルにはルールの検索文字列・置換文字列が含まれるため、ユーザーのローカル環境で管理してください。

## 匿名化漏れチェック

匿名化を実行すると、匿名化後のコードをローカルでスキャンし、メールアドレス、IPv4アドレス、URL、Windows/Unix絶対パス、文字列リテラルが設定された認証情報らしき項目を候補として表示します。Javaの識別子をCamelCaseで分割し、package/importの要素も含めて、一般的なJava用語の除外リストと照合した固有名称候補を表示します。大文字小文字が異なる候補は検出時にまとめますが、匿名化ルール自体はこれまでどおり大文字小文字を区別します。

候補を選ぶと出現回数と行番号を確認できます。固有名称候補は、その場で検索文字列が入力されたルール追加画面を開けます。置換文字列はユーザーが指定してください。誤検出した固有名称候補は、現在のファイルを開いている間だけ無視できます。認証情報候補では実際の値を表示しません。

**この機能は匿名化漏れの可能性がある情報を機械的に検出する補助機能であり、機密情報が完全に除去されたことを保証するものではありません。** 検出結果はユーザーが確認し、最終判断してください。一般的な文字列や独自形式の秘密情報などを誤検出したり、検出できなかったりする可能性があります。

## 対応範囲と今後の予定

現在はテキストファイル1ファイル単位の処理と、主にJavaコード向けのヒューリスティックな匿名化漏れチェック・トークンベース復元に対応しています。完全なJavaパーサーではなく、ディレクトリ一括処理、Gitリポジトリ単位の処理、バイナリファイルの処理は行いません。将来的にディレクトリ単位の対応を検討しています。

匿名化処理と漏れチェックはGUI（`app.py`）から独立した `sanitizer.py` と `leak_checker.py` に実装しています。一般的なJava用語と識別子の接尾語は `src/code_sanitizer/data/` 内のテキストファイルで管理します。ディレクトリ対応を追加する場合は、ファイル列挙や各ファイルの入出力を扱う処理を追加し、既存のテキスト匿名化・漏れチェックロジックを再利用できます。
